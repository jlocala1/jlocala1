## The longer version

<details>
<summary><b>🔊 How the wake word models got good</b></summary>

<br>

Trained and evaluated on a **4x V100 cluster** behind a false-alarms-per-hour harness, which is the metric that actually matters for something always listening.

- **The accent blind spot.** Recall on non-American English was 11%. Rebalancing the training data and retraining took it past 90%.
- **Cross-phrase false triggers.** One wake word firing on another, at 56%. Tightening the threshold fork and negative sampling cut it to 2%.
- **Inherited, not greenfield.** I picked this up from a previous intern's unmerged work, so a good chunk was diagnosing why the existing models underperformed before writing anything new.

Shipped into MIE's shared React design system, [mieweb/ui](https://github.com/mieweb/ui), running through ONNX Runtime and WebAssembly in a Web Worker.

</details>

<details>
<summary><b>🎬 The editing agent, and what's public</b></summary>

<br>

Instead of letting the model rewrite a transcript directly, it emits **validated edit operations against an immutable snapshot**. Every edit is auditable and reversible, and a malformed operation fails validation rather than silently corrupting the output.

I also took the tool from prototype to production on the company's Linux cluster: a GitHub Actions pipeline with health-checked auto-rollback that deploys in **under two minutes**, running unattended since a customer conference.

Most of the editor work is public in [mieweb/ui](https://github.com/mieweb/ui/commits/main/?author=jlocala1):

- A real undo and redo stack the editor never had
- Drag selection that follows the pointer past the pane and auto-scrolls at the edges
- Selection-wide playback speed, with markers that survive a transcript rebuild
- A regression suite for the edge cases that kept biting

Plus a display-title metadata key in the resumable upload layer, [mieweb/pulsevault](https://github.com/mieweb/pulsevault), wired through [mieweb/pulse](https://github.com/mieweb/pulse).

</details>

<details>
<summary><b>🚦 The validation layer</b></summary>

<br>

The reports carry LLM-generated findings, so I needed a way to stop it publishing things that were never in the data. The validation layer **checks every generated claim against the underlying records** and rejects anything unverifiable before it reaches the report.

- Converts BlueCity and Ouster LiDAR data into automated traffic safety reports
- Scripts the vendor's portal with Playwright for auth, date ranges, and multi-panel exports
- Derives peak demand, turning movement, and jaywalking origin-destination metrics with pandas
- Validated end to end, live collection through a PostgreSQL ingest of **500,000+ records**, behind pytest and GitHub Actions CI
- A dependency-free browser interface (Python standard library only) so non-technical users can run it, regenerating any stored date range in about **19 seconds**

Contributed to a six-month analysis delivered to the Prince George's County Department of Public Works and Transportation.

</details>

<details>
<summary><b>🎙️ Two transcription backends and a retrieval layer</b></summary>

<br>

Engineering on an open-source agentic AI platform (**790+ stars**).

- A Python speech-to-text pipeline for MP3 and MP4, producing timestamped transcripts synced to a Next.js viewer with click-to-seek navigation
- **Two backends, deliberately different tradeoffs.** A Python service running Whisper in a sidecar, and a JavaScript sherpa-onnx version running in-process for simpler self-hosted deploys
- A multi-model routing system that switches between OpenAI and Anthropic by task type
- Document ingestion and metadata extraction over a PostgreSQL and pgvector retrieval layer, feeding downstream agentic workflows

</details>

<details>
<summary><b>⚽ EPV, field goals, and defender ratings</b></summary>

<br>

**Expected Possession Value.** Random Forest models trained on tracking and event data from **500+ MLS matches** recursively evaluate shot, pass, and dribble decisions through Bellman-style action-value calculations, personalized across **1,000+ individual players**. I engineered the spatiotemporal features that give it game context: a pitch control model, defensive positioning metrics, and passing lane analysis. The recursive formulation is what lets it value a decision by what it makes possible next, not just what immediately happened.

**Field goal prediction for the Cleveland Browns.** XGBoost at **90%+ accuracy** on a Trackman dataset of 3,800+ kicks covering direction, speed, height, distance, ball rotation, and launch angle. I worked directly with the Browns' Research and Strategy team on player evaluation and kicking strategy.

**Defender evaluation dashboard.** 2,000+ players across Europe's top five leagues, XGBoost with PCA and Optuna tuning, shipped as an interactive Tableau dashboard with position filtering and multi-season comparison.

</details>

<details>
<summary><b>🏆 Predicting the 2026 World Cup</b></summary>

<br>

[**WorldCupPredictor**](https://github.com/jlocala1/WorldCupPredictor) forecasts matches and simulates the tournament.

- Three calibrated models (logistic regression, random forest, XGBoost) voting in an ensemble
- **62 engineered features**: form, head-to-head history, Elo, FIFA rankings, positional metrics
- A four-tier cascading scraper across Understat, Transfermarkt, fotmob, and fbref, so a missing source degrades instead of breaking the run
- Monte Carlo simulation respecting FIFA's actual 2026 bracket, including penalty shootouts
- Honest time-based splits: train 2010 to 2021, validate 2022 to 2024, test on 2025 through early 2026
- **Test log loss 0.827**, benchmarked against bookmaker and FiveThirtyEight baselines, with an LLM as an extra baseline

</details>
